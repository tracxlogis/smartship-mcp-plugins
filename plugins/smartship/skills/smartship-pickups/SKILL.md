# SmartShip 픽업 관리

픽업 화면의 신청 업무를 대화로 수행한다. **픽업 신청은 2단계(생성 → 확정)** 이며, 생성만으로는
픽업이 잡히지 않는다. 순서: **① 대기 주문 조회 → ② 가능일 확인 → ③ 신청 생성(비용 확인) → ④ 확정**.

## 화면 기본 조회 조건 (사용자가 조건을 말하지 않으면 이 값을 쓴다)

- `list_pickup_waiting_orders`: 기간 **최근 30일(오늘 포함)** · 검색 타입 `BN`(QSP, 다건은 `|` 결합) ·
  송장출력 여부 `print_yn` 전체(빈값) · 도착국가/판매사이트 전체(빈값)
- 화면과 대기 건수가 다르면 기간과 `print_yn` 조건부터 대조한다.

## 1. 대기 주문 조회

- `list_pickup_waiting_orders` — 픽업 신청 가능한 대기 주문 + 배송사·출고주소·대형화물 단위
  픽업 그룹 요약. "픽업할 거 있어?" 질문은 여기서 시작한다.

## 2. 가능일·비용 확인

- `check_pickup_date` — 국가/일자 기준 픽업 가능 여부. 사용자가 날짜를 지정하면 신청 전에 반드시 확인.
- `get_pickup_fee` — 생성된 픽업번호의 픽업비·통화 조회.

## 3. 신청 (쓰기 — 반드시 아래 절차, 전부 `confirm=true`)

1. `create_pickup_request` — 픽업 요청 레코드를 생성하고 픽업비를 반환한다.
   **이 단계는 아직 확정이 아니다.** 반환된 비용·대상 주문을 사용자에게 보여준다.
2. 사용자가 비용을 보고 동의하면 `confirm_pickup_request` — 실제 픽업 스케줄
   (인도는 매니페스트)로 확정한다. 동의 없이 확정하지 않는다.
3. 취소 요청 시 `cancel_pickup` — 픽업번호 기준 취소.

- `batch_manifest_india` — 인도(IN) 셀러 전용: 검색 조건의 픽업 대기 주문 일괄 매니페스트.
  대상 건수를 먼저 보여주고 동의 후 실행한다.

## 규칙

- 신청 흐름 중간에 사용자가 이탈하면 상태를 명확히 보고한다: "생성만 되고 확정 전"(비용 발생 전)인지
  "확정 완료"인지 구분해서 알려준다.
- 픽업 주소 변경·주소록 관리는 현재 도구가 없다 — 주소록 화면(/addressbook) 이용을 안내한다.
- 픽업비는 통화와 함께 보고하고, 확정 후에는 픽업번호를 반드시 사용자에게 남긴다.
